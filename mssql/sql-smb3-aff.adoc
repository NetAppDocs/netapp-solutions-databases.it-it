[role="lead"]
Distribuisci SQL Server 2025 su Windows Server 2025 con database utente, log delle transazioni, TempDB e backup su condivisioni SMB 3 a disponibilità continua su un sistema AFF NetApp. Questa procedura include la configurazione della SVM ONTAP, dei volumi e delle condivisioni, l'installazione di SQL Server e la protezione dei database con SnapCenter.



[[scope]]
[[intro-scope]]
== Ambito

Questa procedura distribuisce un'istanza standalone di SQL Server 2025 su un singolo host Windows Server 2025, con database utente, log delle transazioni, TempDB e backup su condivisioni SMB 3 a disponibilità continua (CA). Lo stesso modello di storage si applica anche alle istanze del cluster di failover di SQL Server (FCI) e ai gruppi di disponibilità Always On, ma la relativa configurazione specifica del cluster non è trattata. Anche l'ottimizzazione delle prestazioni e il dimensionamento di SQL Server non rientrano nell'ambito di questa procedura. Per i vantaggi, i componenti della soluzione, i principi di progettazione e una spiegazione di come funziona la disponibilità continua, vedi link:sql-smb3-aff-overview.html["Scopri SQL Server 2025 su NetApp AFF con disponibilità continua SMB 3"].



[[audience]]
[[intro-audience]]
== Pubblico

Questa procedura è destinata a:

* *Amministratori dello storage*, che configurano il cluster ONTAP, l'SVM, i volumi e le condivisioni SMB.
* *Amministratori di Windows e Active Directory*, che preparano l'host Windows Server 2025, gli account di servizio e la rete.
* *Amministratori di database*, che installano e configurano SQL Server 2025 e impostano il backup e il ripristino.


Si presuppone una conoscenza di base di ONTAP System Manager, Windows Server e dell'amministrazione di SQL Server.

| Account del servizio SQL Server | `{svc-account}` (account di dominio) 
|===
[cols="1,1,1,2"]
|===
| Volume / condivisione | Dimensione | Percorso UNC | Contenuto 


| `sql1_data` | 1024 GiB | `+\\a50-sql\sql1_data+` | File di dati del database utente (`.mdf`, `.ndf`) 


| `sql1_log` | 512 GiB | `+\\a50-sql\sql1_log+` | File di log delle database transaction del database utente (`.ldf`) 


| `sql1_tempdb` | 500 GiB | `+\\a50-sql\sql1_tempdb+` | File di dati e di log di TempDB

[[prerequisites]]
== Prerequisiti

Assicurati che i seguenti requisiti siano soddisfatti prima di iniziare:

.NetApp ONTAP
* La coppia HA AFF è installata e il cluster è configurato e integro.
* La licenza CIFS (SMB) è installata. È inclusa in ONTAP One.
* Su ogni nodo esiste almeno un aggregato di dati (livello locale).
* NTP sincronizza l'ora tra il cluster e Active Directory. La differenza massima consentita tra gli orologi per Kerberos è di 5 minuti.
* Le porte della rete dati, il dominio di broadcast e, facoltativamente, le VLAN per le LIF SMB sono configurati.


.Active Directory e DNS
* È disponibile un dominio Active Directory e i server DNS sono raggiungibili dai LIF dati SVM.
* Hai un account con l'autorizzazione a creare oggetti computer nell'unità organizzativa di destinazione, per il server CIFS.
* Per i servizi SQL Server Database Engine e SQL Server Agent è disponibile un account utente di dominio dedicato come account di servizio.



IMPORTANT: SQL Server deve essere eseguito con un *account di dominio* quando i suoi file si trovano su una condivisione SMB. Agli account virtuali predefiniti (`NT SERVICE\MSSQLSERVER`) e agli account locali non può essere concesso l'accesso a una condivisione di file remota.

.Server Windows
* Windows Server 2025 (Desktop Experience) è installato, aggiornato e unito al dominio.
* Sono disponibili il supporto di installazione (ISO) di SQL Server 2025 e un product key valido (o un'edizione gratuita).


.Requisiti e limitazioni SMB per SQL Server su ONTAP
* SMB 3.0 o versione successiva deve essere abilitato sulla SVM.
* Tutti i volumi che ospitano le condivisioni CA devono utilizzare lo stile di sicurezza *NTFS* e devono essere stati NTFS fin dall'inizio.
* SMB Direct (RDMA) non è supportato.
* ReFS non è supportato. ONTAP (WAFL) fornisce il file system per le condivisioni.

== Passaggio 2: Crea e configura la macchina virtuale di storage (SVM)

Usa una SVM dedicata per SQL Server. L'SVM si unisce ad Active Directory come server CIFS e fornisce un LIF dati SMB su ciascun nodo della coppia HA.

.Passaggi
. Crea l'SVM con System Manager o la CLI:
+
[role="tabbed-block"]
====
.System Manager
--
.. In System Manager, vai a menu:Cluster[VM di storage] e fai clic su *+ Add*.
+
.Mostra esempio
[%collapsible]
=====
image:sql25_smb_bp_006.png["Cluster > VM di storage > Aggiungi"]

=====
.. Inserisci il *nome della Storage VM* `a50-sql`. In *Protocollo di accesso*, seleziona la scheda *SMB/CIFS, NFS, S3* e seleziona *Abilita SMB/CIFS*.
+
.Mostra esempio
[%collapsible]
=====
image:sql25_smb_bp_007.png["Aggiungi VM di storage - nome e protocollo"]

=====
+

NOTE: Il nome della Storage VM è il nome SMB del server CIFS.

.. Inserisci le informazioni di Active Directory (dominio, nome amministratore, password e OU) e le informazioni DNS (dominio DNS e server dei nomi).
.. In *Interfaccia di rete*, configura un LIF dati su *ciascun* nodo.
+

TIP: Un LIF per nodo fornisce a SQL Server un percorso diretto (locale) verso ciascun nodo ed è un prerequisito per SMB multichannel e per il failover senza interruzioni. Usa porte da 25 GbE o più veloci e la stessa MTU end-to-end.

+

NOTE: Devi registrare queste interfacce di rete nel DNS server. Per dettagli, vedi https://docs.netapp.com/us-en/ontap-system-manager-classic/smb-config/task_mapping_smb_server_dns_server.html["Associa il server SMB al DNS server"^].

.. Fai clic su *Salva*. System Manager crea l'SVM, il volume root, i LIF e la configurazione DNS e aggiunge il server CIFS al dominio.
.. Verifica il volume root SVM (`a50_sql_root` nel laboratorio). Deve utilizzare lo stile di sicurezza *NTFS*, altrimenti le condivisioni SMB non funzioneranno. Vai al menu:Storage[Volumes], seleziona il volume root e fai clic su *Edit* per rivederne le impostazioni.
+
.Mostra esempio
[%collapsible]
=====
image:sql25_smb_bp_012.png["Modifica il volume root SVM a50_sql_root"]

=====


--
.ONTAP CLI
--
I seguenti comandi creano la stessa configurazione dalla riga di comando. Sostituisci i valori segnaposto tra parentesi angolari.

[source, console]
----
cluster::> vserver create -vserver a50-sql -rootvolume a50_sql_root -aggregate <aggr_node1> -rootvolume-security-style ntfs

cluster::> vserver modify -vserver a50-sql -allowed-protocols cifs

cluster::> network interface create -vserver a50-sql -lif a50-sql_smb_n1 -service-policy default-data-files -home-node <node1> -home-port <port> -address 192.168.175.138 -netmask <netmask>
cluster::> network interface create -vserver a50-sql -lif a50-sql_smb_n2 -service-policy default-data-files -home-node <node2> -home-port <port> -address 192.168.175.139 -netmask <netmask>

cluster::> vserver services name-service dns create -vserver a50-sql -domains sapcc.stl.netapp.com -name-servers <dns1>,<dns2>

cluster::> vserver cifs create -vserver a50-sql -cifs-server A50-SQL -domain sapcc.stl.netapp.com -ou CN=Computers
----
--
====
. [[svm-smb-options,Configura le opzioni del server SMB]]Configura le opzioni del server SMB. Verifica che le opzioni SMB necessarie per SQL Server siano abilitate sull'SVM:
+
[source, console]
----
cluster::> set -privilege advanced
cluster::*> vserver cifs options show -vserver a50-sql -fields smb3-enabled,is-multichannel-enabled,is-large-mtu-enabled,copy-offload-enabled,shadowcopy-enabled
cluster::*> vserver cifs options modify -vserver a50-sql -smb3-enabled true -is-multichannel-enabled true -is-large-mtu-enabled true -copy-offload-enabled true -shadowcopy-enabled true
cluster::*> set -privilege admin
----
+
[cols="1,3"]
|===
| Opzione | Scopo 


| `smb3-enabled` | Per la disponibilità continua delle condivisioni è necessario SMB 3.x. 


| `is-multichannel-enabled` | SMB multicanale utilizza diverse connessioni TCP e percorsi di rete per un throughput maggiore e una resilienza superiore. 


| `is-large-mtu-enabled` | Consente operazioni di lettura e scrittura SMB fino a 1 MB. 


| `copy-offload-enabled` | Offload della copia ODX; il sistema storage esegue le copie internamente. 


| `shadowcopy-enabled` | VSS remoto per condivisioni SMB. Necessario per le applicazioni di backup che utilizzano VSS per condivisioni SMB. 
|===
. Verifica che il server CIFS sia registrato nel DNS e che possa essere risolto dall'host di SQL Server:
+
[source, powershell]
----
PS C:\> Resolve-DnsName a50-sql.sapcc.stl.netapp.com
----

== Passaggio 4: Regola le impostazioni del volume

Esamina e regola le impostazioni di spazio e snapshot di ciascun volume di SQL Server.

.Passaggi
. Nell'elenco dei volumi, passa con il puntatore sul volume e fai clic sull'icona della matita (*Edit*).
+
.Mostra esempio
[%collapsible]
====
image:sql25_smb_bp_023.png["Icona di modifica nell'elenco dei volumi"]

====
. Configura il volume come segue (mostrato per `sql1_data`):
+
** *Abilita thin provisioning*: selezionato
** *Ridimensiona automaticamente*: selezionato, *Modalità di crescita automatica*: *Grow*, *Dimensione massima*: ad esempio `1.3 TiB` (circa il 125–130 % della dimensione del volume)
** *Abilita riserva frazionaria (100%)*: deselezionata
** *Tipo di sicurezza*: `NTFS`
** *riserva di Snapshot %*: `5` (`0` per `sql1_tempdb`)
** *Pianifica snapshot*: deselezionato. Gli snapshot non coerenti con l'applicazione non sono utili per SQL Server; usa NetApp SnapCenter invece.
** *Mostra la directory degli snapshot ai client*: facoltativo (il laboratorio l'ha lasciata selezionata; deselezionandola si nasconde `~snapshot` dalla condivisione)
+
Fai clic su *Salva* e ripeti l'operazione per `sql1_log`, `sql1_tempdb` e `sql1_backups`.

+
.Mostra esempio
[%collapsible]
====
image:sql25_smb_bp_024.png["Modifica le impostazioni del volume sql1_data,width=450"]

====




[source, console]
----
cluster::> volume modify -vserver a50-sql -volume sql1_data -space-guarantee none -fractional-reserve 0 -percent-snapshot-space 5 -snapshot-policy none -autosize-mode grow -max-autosize 1.3TB

TIP: Mantieni attive le funzionalità di efficienza dello storage (deduplicazione, compressione, compaction) su AFF. Sono inline e non hanno alcun impatto misurabile sulle prestazioni di SQL Server.

*** *Consenti ai client di accedere alla directory degli snapshot*: deselezionato
*** *Crittografa i dati durante l'accesso a questa condivisione*: deselezionato (facoltativo, a seconda dei tuoi requisiti di sicurezza)

[[step-6-prepare-windows-server-2025]]

== Passaggio 6: Prepara Windows Server 2025

Esegui i seguenti passaggi sull'host di SQL Server `{host}` come amministratore di dominio.

.Passaggi
. Verifica che il server sia aggiunto al dominio e che il server CIFS sia risolvibile (vedi <<svm-smb-options>>).
. Assicurati che l'account del servizio SQL Server esista in Active Directory, ad esempio `SAPCC\sql1admin`. Usa lo stesso account per Database Engine e per SQL Server Agent, oppure usa un account separato per ciascuno. Qualunque opzione tu scelga, concedi a ciascun account l'accesso a tutte e quattro le condivisioni.
. Verifica l'accesso alle condivisioni nel contesto di sicurezza dell'account di servizio:
+
[source, powershell]
----
PS C:\> runas /user:SAPCC\sql1admin "cmd /c dir \\a50-sql\sql1_data && echo test > \\a50-sql\sql1_data\write-test.txt && del \\a50-sql\sql1_data\write-test.txt"
----
. Apri la porta di SQL Server nel firewall di Windows:
+
[source, powershell]
----
PS C:\> New-NetFirewallRule -DisplayName "SQL Server (TCP 1433)" -Direction Inbound -Protocol TCP -LocalPort 1433 -Action Allow
----
. Verifica la connessione SMB all'SVM. Il dialetto deve essere 3.x e `ContinuouslyAvailable`deve essere `True`:
+
[source, powershell]
----
PS C:\> dir \\a50-sql\sql1_data | Out-Null
PS C:\> Get-SmbConnection -ServerName a50-sql | Format-Table ServerName,ShareName,Dialect,ContinuouslyAvailable,Encrypted,Signed
PS C:\> Get-SmbMultichannelConnection -ServerName a50-sql
----



NOTE: Per impostazione predefinita, Windows Server 2025 richiede la firma SMB per tutte le connessioni SMB outbound. ONTAP supporta la firma SMB e la negozia automaticamente. La firma aggiunge un sovraccarico della CPU su entrambi i lati, quindi includila nei tuoi test delle prestazioni. Non disabilitare la firma senza una verifica di sicurezza.

.Mostra esempio
[%collapsible]

SELECT DB_NAME(database_id) AS database_name,

[[use-an-ontap-cli-script-to-configure-the-storage-in-one-pass]]
== Usa uno script CLI di ONTAP per configurare lo storage in un'unica operazione

Lo script seguente contiene la configurazione completa dello storage di questa procedura. Sostituisci i valori tra parentesi angolari prima di eseguirlo.

[source, console]
----
# --- SVM -----------------------------------------------------------------
vserver create -vserver a50-sql -rootvolume a50_sql_root -aggregate <aggr_node1> -rootvolume-security-style ntfs
vserver modify -vserver a50-sql -allowed-protocols cifs

network interface create -vserver a50-sql -lif a50-sql_smb_n1 -service-policy default-data-files -home-node <node1> -home-port <port> -address 192.168.175.138 -netmask <netmask>
network interface create -vserver a50-sql -lif a50-sql_smb_n2 -service-policy default-data-files -home-node <node2> -home-port <port> -address 192.168.175.139 -netmask <netmask>

vserver services name-service dns create -vserver a50-sql -domains sapcc.stl.netapp.com -name-servers <dns1>,<dns2>
vserver cifs create -vserver a50-sql -cifs-server A50-SQL -domain sapcc.stl.netapp.com -ou CN=Computers

set -privilege advanced
vserver cifs options modify -vserver a50-sql -smb3-enabled true -is-multichannel-enabled true -is-large-mtu-enabled true -copy-offload-enabled true -shadowcopy-enabled true
set -privilege admin

# --- Volumes -------------------------------------------------------------
volume create -vserver a50-sql -volume sql1_data    -aggregate <aggr_node1> -size 1TB   -security-style ntfs -junction-path /sql1_data    -space-guarantee none -fractional-reserve 0 -percent-snapshot-space 5 -snapshot-policy none -autosize-mode grow -max-autosize 1.3TB
volume create -vserver a50-sql -volume sql1_log     -aggregate <aggr_node2> -size 512GB -security-style ntfs -junction-path /sql1_log     -space-guarantee none -fractional-reserve 0 -percent-snapshot-space 5 -snapshot-policy none -autosize-mode grow -max-autosize 650GB
volume create -vserver a50-sql -volume sql1_tempdb  -aggregate <aggr_node2> -size 500GB -security-style ntfs -junction-path /sql1_tempdb  -space-guarantee none -fractional-reserve 0 -percent-snapshot-space 0 -snapshot-policy none -autosize-mode grow -max-autosize 650GB
volume create -vserver a50-sql -volume sql1_backups -aggregate <aggr_node1> -size 2000GB -security-style ntfs -junction-path /sql1_backups -space-guarantee none -fractional-reserve 0 -percent-snapshot-space 5 -snapshot-policy none -autosize-mode grow -max-autosize 2600GB

# --- CA shares -----------------------------------------------------------
vserver cifs share create -vserver a50-sql -share-name sql1_data    -path /sql1_data    -share-properties oplocks,browsable,changenotify,continuously-available
vserver cifs share create -vserver a50-sql -share-name sql1_log     -path /sql1_log     -share-properties oplocks,browsable,changenotify,continuously-available
vserver cifs share create -vserver a50-sql -share-name sql1_tempdb  -path /sql1_tempdb  -share-properties oplocks,browsable,changenotify,continuously-available
vserver cifs share create -vserver a50-sql -share-name sql1_backups -path /sql1_backups -share-properties oplocks,browsable,changenotify,continuously-available

# --- Share permissions (repeat for each share) ----------------------------
vserver cifs share access-control create -vserver a50-sql -share sql1_data -user-or-group SAPCC\sql1admin -permission Full_Control
vserver cifs share access-control delete -vserver a50-sql -share sql1_data -user-or-group Everyone

# --- Verification ----------------------------------------------------------
vserver cifs show -vserver a50-sql
vserver cifs share show -vserver a50-sql -fields share-name,path,share-properties
vserver cifs session file show -vserver a50-sql -fields share,path,continuously-available
----

TIP: Distribuisci i volumi tra gli aggregati di entrambi i nodi, ad esempio dati e backup sul nodo 1 e log e TempDB sul nodo 2. In questo modo usi le risorse di entrambi i controller.
