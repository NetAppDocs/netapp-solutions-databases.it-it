= Flusso di lavoro di Google Cloud NetApp Volumes per implementare Oracle Database 26ai ad alta disponibilità
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
Utilizza Google Cloud NetApp Volumes iSCSI storage a blocchi per implementare Oracle Database 26ai ad alta disponibilità con Oracle Data Guard su Google Compute Engine. Questo flusso di lavoro ti guida attraverso le opzioni di implementazione, il provisioning dell'infrastruttura, l'installazione del software Oracle e la configurazione dell'alta disponibilità, sfruttando la replica a livello di storage di GCNV per un'inizializzazione rapida dello standby.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-1.png["Uno"]link:gcnv-oracle-solution-architecture.html["Esamina l'Architettura della soluzione"]
[role="quick-margin-para"]
Scopri l'architettura di Google Cloud NetApp Volumes per l'alta disponibilità di Oracle Database 26ai, inclusi la progettazione dello storage a blocchi iSCSI GCNV, l'integrazione con Data Guard e la topologia dello storage.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-2.png["Due"]link:gcnv-oracle-deployment-options.html["Esamina le opzioni e i requisiti di implementazione"]
[role="quick-margin-para"]
Confronta i livelli di deployment da dev/test a produzione HA e conferma i prerequisiti di infrastruttura, accesso e software.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-3.png["Tre"]link:gcnv-oracle-access-and-apis.html["Verifica l'accesso e le API"]
[role="quick-margin-para"]
Conferma l'accesso richiesto, l'abilitazione delle API, i prerequisiti di rete e la sincronizzazione dell'ora.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-4.png["Quattro"]link:gcnv-oracle-provision-compute.html["Esegui il provisioning delle istanze Google Compute Engine"]
[role="quick-margin-para"]
Crea macchine virtuali per il database primario, il database di standby e l'osservatore Fast-Start Failover.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-5.png["Cinque"]link:gcnv-oracle-provision-storage.html["Effettua il provisioning dello storage iSCSI GCNV"]
[role="quick-margin-para"]
Crea pool di storage GCNV e volumi iSCSI, configura il multipath e imposta i gruppi di dischi ASM.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-6.png["Sei"]link:gcnv-oracle-install-software.html["Installa Oracle Grid Infrastructure e Oracle Database 26ai"]
[role="quick-margin-para"]
Installa il software Oracle Grid Infrastructure e Oracle Database 26ai su entrambi gli host del database.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-7.png["Sette"]link:gcnv-oracle-primary-database.html["Creare il database primario"]
[role="quick-margin-para"]
Crea il database Oracle principale con storage ASM e configura Oracle Restart.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-8.png["Otto"]link:gcnv-oracle-standby-database.html["Creare il database standby"]
[role="quick-margin-para"]
Inizializza il database standby utilizzando la replica GCNV, gli snapshot o i cloni, quindi registralo con Oracle Restart. Tutti i livelli HA completano questo passaggio.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-9.png["Nove"]link:gcnv-oracle-standby-finalize-dg.html["Finalizza il database standby per Data Guard"]
[role="quick-margin-para"]
Crea log di redo di standby, abilita flashback, attiva redo shipping e verifica lo stato di Data Guard. *Specifico per livello:* Obbligatorio solo per il livello Prod HA (Data Guard + FSFO).

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-10.png["Dieci"]link:gcnv-oracle-data-guard.html["Configura Data Guard Broker e Fast-Start Failover"]
[role="quick-margin-para"]
Abilita il broker, crea la configurazione di Data Guard, abilita FSFO e configura l'Observer. *Specifico per livello:* Obbligatorio solo per il livello Prod HA (Data Guard + FSFO).
